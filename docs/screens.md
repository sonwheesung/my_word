## 3. AddWordScreen

`wordId` 가 있으면 수정 모드. 들어온 화면(`previousScreen`)으로 돌아간다.

| 입력 | 상한 |
|------|------|
| 단어 | 100자. 소문자로 바꾸지 않는다(독일어 명사 등) |
| 뜻 | 한 칸 200자 · 최대 `LIMITS.meanings = 10` |
| 예문 · 번역 | 각 300자 · 최대 `LIMITS.examples = 5` |
| 태그 | 30자 · 최대 `LIMITS.tags = 10` · 엔터로 추가 · 중복 거부 |
| 메모 | `MEMO_MAX = 500` · 100자를 넘으면 카운터 표시 |

- 예문 · 태그 · 메모는 접이식 `선택 항목` 안에 있다(기본 접힘)
- `뜻 찾기`(`dictionaryService.lookup`): 결과가 뜻 · 예문 · 태그를 덮어쓰고 메모를 비운다. 예문은 영어 단어만. 단어 칸에서 엔터도 같다
- 저장 검증: 카테고리 · 단어 · 뜻 하나 이상. 같은 카테고리에 같은 단어가 있으면 확인창 뒤 저장 가능
- 수정 모드는 저장 전 확인창. 저장 중 입력과 버튼 비활성

**Props**: `wordId?` · `onWordAdded` · `onBack`

## 7. QuizScreen

**들어오는 길 넷**: 퀴즈 설정 · 홈 복습 배너 · 플래시카드 마무리 · 결과 화면의 다시 풀기.
뒤의 둘(배너 · 플래시카드)은 단어 id 목록(`retryWordIds`)을 들고 오고, 카테고리 없이 객관식 · 단어→뜻 으로 고정된다.

**문제 유형** (`QuizType`)

| 유형 | 제시 | 답 |
|------|------|------|
| `word_to_meaning` | 단어 | 뜻 |
| `meaning_to_word` | 뜻 | 단어 |
| `example_to_meaning` | 예문 | 뜻 (주관식 `mixed` 에서만) |
| `translation_to_example` | 번역 | 예문 (주관식 `mixed` 에서만) |

**단어 고르기**
- `random` · `mixed`: 섞어서 앞에서부터 · `recent`: 등록 최신순
- `weak`: 정답률 50% 미만을 낮은 순으로(`getWeakWordIds`). 모자라면 나머지에서 무작위로 채운다
- `review`: 고른 카테고리 안에서 만기 지난 단어(오래 밀린 순) → 한 번도 안 푼 단어(오래된 순).
  **만기가 문제 수보다 적으면 만기만 낸다**(억지로 채우지 않는다). 만기 0이면 무작위
- 뜻이 비어 있는 단어는 뺀다
- `mixed` 유형 배정: 객관식은 앞의 두 유형 반반, 주관식은 0.3 · 0.3 · 0.2 · 0.2(예문이 없으면 `word_to_meaning`)

**객관식 보기**: 같은 퀴즈의 단어 풀(카테고리가 없으면 전체 단어)에서 정답과 다른 것 3개. 모자라면 더미(`기억나지 않음` 등)로 채운다.

**채점** (`normalizeForCompare` = trim · 소문자 · NFC)

### 🔴 풀던 중에 나갈 수 있다 — 그리고 **나가도 안 사라진다** (2026-10-14)

2026-10-14 까지는 **나가는 문이 아예 없었다.** 뒤로가기를 누르면 띠 하나(*"끝까지 풀어 주세요"*)를
띄우고 그 자리에 세워 뒀다. 이유는 *"문제를 만드는 데 돈이 들었고 그냥 나가면 사라진다"* 였는데,
**그 막기는 지키지도 못했다**:

```
시험 내용은 마지막 문제를 풀어야 저장됐다 — 중간 저장이 없었다
  홈 버튼 · 앱 종료 · 오래 끊긴 전화  → 똑같이 사라진다   ✗ 못 막는다
  뒤로가기                          → 막혀 있다          ← 이것 하나뿐
```

갇힌 사람은 앱을 강제로 끄므로 **막을수록 더 자주 잃는 구조**였다
(사장님: *"그냥 나갈 수 있게 하면 안돼?"*).

🔴 **그래서 고친 방향은 「나가게 해 준다」가 아니라 「나가도 안 사라지게 한다」이다.**
문만 열면 정말로 잃기 시작한다. 저장이 먼저다.

| 언제 적나 | 왜 |
|---|---|
| 문제가 도착한 순간 | 90초를 기다린 직후가 **사람이 가장 많이 나가는 자리**다(전화·알림·화면 꺼짐) |
| 문제를 고를 때마다 | 앱이 죽는 경로(홈 버튼·강제 종료)를 덮는다. **나갈 때만 적으면 그 경로가 그대로 남는다** |
| 「나가기」를 고를 때 | 🔴 **저장이 끝난 뒤에 나간다.** 먼저 나가면 저장이 취소될 수 있다 |

끝내면 비운다 — 안 비우면 성적표를 보고 나온 사람에게 설정 화면이 *"풀던 시험이 있어요"* 라고 한다.

#### 🔴 그래도 **한 자리에만 맡겨 뒀던 것**이 남아 있었다 (2026-10-15)

「풀던 시험」은 **한 판만** 담는다. 새 시험을 시작하면 덮이고, 저장이 실패하면 통째로 없다.
그 하나를 잃으면 **돈이 나간 판이 흔적도 없이 사라졌고**, 다시 하려면 무료 1번을 또 써야 했다.

→ **문제가 도착하는 순간 성적표에도 한 줄을 적는다**(`examService.saveUnplayed`). 성적표는
20판을 들고 있으므로, 거기 남아 있으면 **공짜로** 다시 풀 수 있다(서버를 안 부르는 재시험 통로다).

| 자리 | 회차가 빈 기록을 어떻게 다루나 |
|---|---|
| 성적표 | `최고 0%` 가 아니라 **「아직 안 푸셨어요」**. 0% 는 *다 틀렸다*로 읽힌다 |
| 성적표 버튼 | 「이 시험 풀기」(▶). 그 아래에 **무료 횟수를 안 쓴다**고 적는다 |
| 통계 | 회차가 없으므로 아무것도 안 센다. 처음 푸는 날 `addAttempt` 가 **그때** 넣는다 |
| 버리기 확인 | 성적표에 남아 있으면 **그 사실을 문구가 말한다**(모르면 무료 1번을 또 쓴다) |

🔴 **통계를 두 번 세는 길이 하나 생겼다. 그래서 세기 전에 묻는다.**
성적표에서 푼 판을, 남아 있던 「풀던 시험」으로 또 끝낼 수 있다. `ExamScreen` 은 저장 **전에**
`hasCountedAttempt(examId)` 를 묻고, 이미 회차가 있으면 통계를 건드리지 않는다
(저장한 뒤에 물으면 방금 넣은 회차가 보여서 구분이 사라진다).

🚫 **재시험에는 빈 회차를 쓰지 않는다** — 그 기록에는 회차가 쌓여 있어서 덮으면 지난 성적을 지운다.

- ⚠ **확인 시트의 「계속 풀기」가 물러서는 자리(`onCancel`)다.** 바깥 눌림·끌어 내리기가 같은
  자리로 떨어지므로, 거기에 「나가기」를 걸면 **시트를 실수로 닫은 사람이 시험에서 나가 버린다**
- ⚠ **「나가기」를 빨간색으로 그리지 않는다.** 아무것도 잃지 않기 때문이다. 겁주는 색은 문구
  (*"그대로 남아요"*)와 어긋나고, 나가는 길을 눈에 안 띄게 만드는 것은 「취소 방해」에 가깝다
- 🔴 **한 판만 들고 있는다**(접수증과 같다). 새 시험을 시작하면 사라지므로 설정 화면이 먼저 묻는다
- 🔴 **이어서 풀 때 카테고리·언어는 저장본이 정본이다.** 설정 화면에 떠 있는 값을 쓰면
  성적표의 「단어 담기」가 **엉뚱한 단어장**을 가리킨다
- 저장 키는 `@my_word_exam_progress`(`data-model.md`). 가드는 `__tests__/examService.test.ts`

## 21. SubscriptionScreen (구독 관리 · 해지 · 시안 #21 · 2026-10-16)

설정 › 구독. 상태를 보고 **해지하러 Play 로 가는** 화면이다.

🔴 **설정의 그 줄은 적은 말과 같은 곳으로 보낸다** — 구독 중이면 이 화면, 아니면 **페이월로 바로**
(`onPress={proActive ? onSubscription : onSubscribe}`). 처음에는 말만 갈라 놓고 가는 곳은 늘 이 화면이라,
「구독 알아보기」를 누른 사람에게 **「구독 관리 · 지금은 구독 중이 아니에요」**가 떠서 한 번을 더
눌러야 했다. 타입·테스트 817개가 전부 초록인 채였고 **폰에서 눌러 봐서** 잡혔다(2026-10-16).
→ 아래 빈 상태는 **그대로 남긴다**. 이 화면을 보는 동안 구독이 끝나는 경우가 있다.

🔴 **앱은 구독을 직접 해지할 수 없다. Play 가 주인이다.** 그래서 이 화면이 하는 일은
**상태를 정직하게 보여 주고 Play 로 보내는 것**뿐이다. 구독을 파는 앱은
**앱 안에 관리·해지 경로가 있어야 한다**(Play 구독 정책).

### 상태 셋 — 🔴 **유예가 먼저다**

```
grace     active && inGracePeriod    결제 실패. 유예가 끝나는 날 끊긴다
canceled  active && !willRenew       해지 예약. 결제한 기간 끝까지는 그대로
on        그 밖                       구독 중
```

⚠ **결제가 실패한 뒤 해지까지 누른 사람은 둘 다 참이다.** 「해지 예약」을 먼저 보여 주면
*"11월 13일까지 쓸 수 있어요"* 라고 말하는데 실제로는 **유예가 끝나는 날 끊긴다.**
마음을 바꿔도 그때는 늦다 → **시한이 급하고 할 일이 있는 쪽**을 먼저 보여 준다.

### 지키는 것

- 🚫 **해지를 붙잡지 않는다.** 버튼을 숨기거나 흐리게 하지 않고, 확인 **한 번** 뒤 바로 Play 로
  보낸다. 할인·설문·「정말요?」가 없다(전자상거래법 다크패턴 「취소·탈퇴 방해」)
- 🚫 **해지 버튼을 빨강으로 겁주지 않는다** — 되돌릴 수 있는 일이다
- 🔴 **금액을 적지 않는다.** 서버가 주는 것은 `active · expiresAt · willRenew · inGracePeriod`
  넷뿐이다. 「지금 파는 가격」을 쓰면 가격을 올린 뒤 **옛 가격을 내는 사람에게 새 가격**이 뜬다
- 🔴 **날짜를 지어내지 않는다.** 못 읽으면 그 줄을 **통째로 뺀다**(「없음」도 지어낸 말이다)
- 🟢 **해지해도 남는 것을 먼저 말한다** — 기록 · 재시험 무료 · **쓰지 않은 무료분이 돌아온다**
- ⚠ 월간/연간은 **기기의 스토어 SDK** 에서 읽는다(`activePlanKind`). 모르면 **안 적는다**

## 20. PaywallScreen (구독 결제 · 시안 #20 · 2026-10-16)

무료 10회를 다 쓴 사람이 구독을 사는 화면이다. **구독을 파는 유일한 자리**다.

**Props**: `onBack` · `onDone?`
**들어오는 길**: ① 시험 설정 화면의 무료 판수 카드(다 썼을 때 [구독 알아보기])
② **설정 › 구독**(구독 중이 **아닐** 때) ③ 구독 관리 화면의 빈 상태

### 🔴 돈을 받는 화면이라 지켜야 하는 셋. 전부 법에서 온다

| | |
|---|---|
| 고지가 **버튼 바로 아래** | 가격 · 주기 · 자동 갱신 · 해지 방법. 다른 화면에 숨기면 Play 심사에서 걸린다 |
| 요금제를 **미리 안 고른다** | 전자상거래법 다크패턴 「특정 옵션 사전선택」(2025-02-14 개정 · 공정위 지침 2025-10-24). 고르기 전 버튼은 「요금제를 골라 주세요」 |
| 가격을 **안 지어낸다** | Play 가 준 현지 가격만. 못 받으면 **카드를 회색 자리로 비우고** [다시 시도] |

🚫 **「무제한」이라고 쓰지 않는다.** 하루 호출 한도 · 10분 쿨다운 · 월 예산은 구독자에게도 남는다.

### 🔴 혜택 줄은 **「AI 시험을 날마다 새 문제로」**다 (2026-10-28 · 사장님 지적으로 바꿨다)

전에는 「AI 시험을 판수 제한 없이」였다. **말 자체는 맞았다** — 하루 캡 20은 판수가 아니라
**「새 문제 만드는 호출」**을 세고, 막혀도 시험은 **이미 본 문제로 채워** 나간다:

```
① 창고에서 안 본 문제를 먼저 꺼낸다        모델 호출 0
② 모자라면 만든다                        ← 하루 20회는 여기만 막는다
③ 막혀도 시험은 나간다 — 본 문제로 채운다
④ 창고가 통째로 빈 경우에만 503
```

그런데 **④ 에서 거짓이 된다** — 아주 새 단어만으로 치는데 그날 한도에 닿아 있으면 창고가 비어
한 판도 못 본다. 그리고 「판수 제한 없이」는 **무료 10판 벽을 겪어 본 사람만 알아듣는 말**이다.
→ **날마다 진짜로 리셋되는 것을 말한다.** 한도에 닿아도 거짓이 아니다.

🔴 **숫자를 박지 않는다. 참인 N 이 없다.** 전부 새 문제면 하루 10판쯤(20문제 = 7단어 = 2호출)이고
창고에 있으면 제한이 없다. **20을 판수로 적으면 새 거짓이 된다**(그건 호출 수다).
🔴 **이 줄은 Play 콘솔 혜택 칸 첫 줄과 글자 그대로 같아야 한다**(세 언어 모두) — 앱만 고치면 어긋난다.
⚠ 고칠 자리가 한 곳이 아니다. 같은 말이 **페이월 · 구독 관리 · 설정 · 무료 판수 카드 · 시험 실패 화면**
다섯 곳에 흩어져 있다(2026-10-28 전수 교체).
⚠ 할인율(「34% 아껴요」)은 **두 가격의 숫자로 계산한다.** 글자로 박으면 나라마다, 가격을 바꿀 때마다 거짓이 된다.
⚠ 버튼 글자는 「연 ₩39,000 구독하기」다 — **자리표시자 뒤에 조사를 붙이지 않는다**(§4.5).
「{{price}}으로」는 「$2.99으로」에서 틀린다.

### 🔴 결제가 끝나도 곧바로 구독자가 아니다 (시안 #23 이 이 안에 있다)

Play → RevenueCat 웹훅 → 우리 서버까지 **몇 초**가 걸린다. 그 사이를 실패로 보여 주면
**이미 돈을 낸 사람이 놀란다.** 「확인 중」을 띄우고 `recheckPro(true)` 로 2.5초 간격 6번 묻는다.

- 🔴 **포기해도 실패로 보여 주지 않는다.** 「오래 걸리면 구매 복원을 눌러 주세요」로 바꿀 뿐이다.
- 🔴 **다시 결제하는 길을 두지 않는다.** 오래 걸릴 때의 답은 [구매 복원] 하나다.
- 🔴 `recheckPro` 가 주는 **`null`(못 물어봤다)을 `false` 로 읽지 않는다.** 그러면 네트워크가
  잠깐 끊긴 사람에게 「구독이 아니다」가 된다.
- ⚠ `restore()` 는 **객체**를 준다. `if (await restore())` 는 늘 참이라 실패해도 「찾았다」가 된다
  (만들면서 한 번 그렇게 썼다. 타입 검사가 안 잡는다).

### 결제가 어긋나는 다섯 갈래 — 하나로 접지 않는다

```
cancelled      가장 흔하다. 오류로 안 보여 주고 고른 요금제도 그대로 둔다
already-owned  다시 결제시키지 않는다. 확인만 한다
not-allowed    보호자 승인 거부 · 기기 결제 제한. 「다시 시도」로 안 풀린다
unavailable    가격을 못 받았다 → 「가격 없음」 화면
error          🚫 「돈은 나가지 않았어요」라고 단정하지 않는다
```

## 19. ExamHistoryScreen

## 🔴 통계에 들어가는 것은 1회차뿐이다

```
1회차   내 단어장에 있는 단어의 문제만 · 넘긴 문제 제외 → quiz_results + SRS 만기
2회차~  성적표에만 쌓인다. 정답률·스트릭·만기를 건드리지 않는다
```

같은 문제를 다시 풀면 **외워서 맞힌다.** 그걸 정답률에 넣으면 숫자가 조용히 부푼다.

✅ **실기기 검증 (2026-10-07 · AVD `my_word`)**: 같은 시험을 재시험으로 다시 풀었더니
`quiz_results` 가 **49건에서 그대로 49건** · `@my_word_srs` 저장본 **md5 동일** · 홈의 정답률도
**33% 그대로**였다. 성적표에는 `Attempt 2 15%` 가 쌓이고 `Best` 는 최고점인 **20%** 를 유지했다.
⚠ 재시험은 **즉시** 떴다 — 새 시험의 90초 대기가 없는 것이 서버를 안 부른다는 실물 증거다.

🔴 `wordId` 는 **반드시 내 단어장에서 찾아 쓴다.** 문제는 단어를 글자로만 들고 있고(서버 창고가
공용이라 사용자 번호를 모른다), 못 찾은 것을 가짜 번호로 넣으면 **없는 단어를 가리키는 통계**가
생겨 정답률 화면이 조용히 섞어 보여준다. 못 찾으면 그 문제는 통계에 안 쓴다.

⚠ `__tests__/examService.test.ts` 가 **소스 훑기 + 실제 저장소 동작** 양쪽으로 지킨다.
