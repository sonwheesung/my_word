## [1.3.0] - 작업 중

### 평생 광고 제거 (인앱 상품)

앱의 첫 유료 상품이다. **구독이 아니라 관리형 상품(비소비성)** 이다 — 한 번 사면 영구다.

- **추가**: `expo-iap@5.3.1` (config plugin 자동 등록)
  - `react-native-iap` 은 Expo managed 와 호환되지 않는다. `expo-iap` 는 Expo Module 이라
    CNG 로 붙는다
- **추가**: `src/contexts/PurchaseContext.tsx`
  - 🔴 **진실은 Google Play 에 있다.** `@my_word_ad_free` 는 부팅 직후 광고가 번쩍이는 것을
    막는 캐시일 뿐이고, 매 부팅 `getAvailablePurchases()` 로 다시 확인한다.
    환불되면 목록에서 사라지므로 다음 부팅에 광고가 자동으로 돌아온다
  - 🔴 **Play 조회 실패 시 캐시 값을 유지한다.** 오프라인인 구매자에게 광고를 되돌려주면
    안 된다. 미구매자는 캐시가 `'0'` 이라 그대로 광고를 본다 (fail-to-cache)
  - 🔴 **`finishTransaction` 을 반드시 부른다** (`isConsumable: false`).
    안 부르면 Play 가 3일 뒤 자동 환불한다 — 돈은 받고 광고는 살아나는 최악이 된다
  - ⚠ **서버 영수증 검증을 하지 않는다.** 의도적이다 — 백엔드가 없고 탈취되어도 손해가
    한 건이다. 검증 서버 비용이 그보다 크다. 더 비싼 상품을 붙이면 이 판단을 다시 한다
  - 네이티브 모듈이 없는 환경(Expo Go · 웹)에서 죽지 않도록 방어 require 를 쓴다 —
    기존 광고 코드와 같은 규약이다
- **변경**: 광고 게이팅 3곳
  - `AdBanner.tsx` — `adFree` 면 `null`
  - `useInterstitialAd.ts` — `adFree` 면 **미리 불러오는 것부터 하지 않는다.** show 만 막으면
    보이지 않을 뿐 트래픽은 그대로 나가고, AdMob 정책상으로도 좋지 않다
  - `SettingsScreen` — `광고` 섹션 신설 (구매 · 구매 복원 · 구매 완료 상태)
- **변경**: 버전 1.3.0 (`app.json` · `appConfig.APP_VERSION` 동시 갱신)
- **추가**: 번역 키 12개 (`en.json`). AsyncStorage 는 **새 키 추가만** 했고 기존 스키마와
  CSV 포맷은 건드리지 않았다 (하위호환 제약)

⚠ **성공 문구를 구매 버튼에서 띄우지 않는다.** 결제창을 닫는 것과 결제가 끝나는 것은 다른
사건이고, 실제 지급은 `purchaseUpdatedListener` 가 한다. 버튼은 실패만 알린다.

**검증**: `tsc --noEmit` 통과 · 테스트 140개 통과 · 웹에서 구매/복원 실패 경로와
한국어·영어 문구 확인, 콘솔 에러 0건.
(`App.test.tsx` 스위트 실패는 `expo-linear-gradient` 문제로 **이번 변경 이전부터** 있던 것)

  - **단어와 뜻이 같은 언어면 채우지 않는다** (`same-language`) — Google 이 입력을 그대로
    돌려주므로 뜻이라고 넣으면 오히려 방해가 된다
- **변경**: 품사 라벨이 앱 언어를 따른다 (`constants/partOfSpeech.ts`).
  사전 조회 결과가 태그로 저장되므로 한국어 고정이면 다른 언어 사용자에게 그대로 남는다
  - 요청에 **`hl=en` 을 고정**한다. 이 값을 빼면 Google 이 품사 라벨을 요청의
    `Accept-Language` 에 맞춰 돌려주기 때문에, **같은 코드가 기기 로케일에 따라
    `명사`/`noun`/`Substantiv` 를 준다**(브라우저 검증 중 발견). 영어로 받아 우리 표로 옮긴다
- **알려진 제약**: **예문 자동 수집은 영어 단어만 가능하다.**
  출처인 `dictionaryapi.dev` 에 영어 표제어만 존재한다 — `Apfel`·`猫`·`книга` 같은 유효한
  단어도 다른 언어 코드로는 404다. 영어가 아니면 예문 조회를 시도하지 않고,
  **뜻만 채운 뒤 그 사실을 사용자에게 알린다**(조용히 비워두면 실패로 오해된다)
- **알려진 제약**: 뜻 언어가 **한국어일 때는 영어 단어만** 사전 항목(품사·복수 뜻)을 받는다.
  `de→ko`·`ja→ko` 는 Google 에 사전 데이터가 없어 기본 번역 1개만 온다.
  반대로 뜻 언어가 **영어일 때는 조사한 모든 원본 언어**(de·fr·ja·ar·zh·ko)가 사전 항목을 받는다
  — 외국어 UI 사용자가 오히려 더 잘 동작한다. 언어쌍별 데이터 문제이며 앱에서 해결할 수 없다
- **추가**: 테스트 32건 (언어 결정 15건, 사전 계약 17건)

### 2026-08-09 (다국어 대응)

전 세계 배포를 앞두고 "영어를 전제한 코드"를 걷어냈다. 저장 계층(AsyncStorage·CSV)은
원래부터 인코딩 가정이 없어 손대지 않았고, 저장 **주변**만 고쳤다.

- **수정**: 단어·예문 입력의 강제 대소문자 변환 제거 (`AddWordScreen`)
  - 단어 첫 글자를 `toLowerCase()` 하고 있어 독일어 명사(`Apfel`→`apfel`)와 고유명사가
    틀린 철자로 저장됐다. 터키어 `İ` 는 `i`+결합 점으로 **글자 수까지 늘어났다**
  - 예문 첫 글자 `toUpperCase()` 도 같은 이유로 제거. 대문자 힌트는 `autoCapitalize`
    (키보드 설정, 데이터를 바꾸지 않음)로 충분하다
- **추가**: 유니코드 정규화 `normalizeForCompare` (`src/utils/text.ts`)
  - 같은 글자의 조합형(NFD)/완성형(NFC)이 `===` 비교에서 달라 중복 검사·검색·**퀴즈 채점**이
    어긋나던 문제. `학습` 은 NFC 2자, NFD 6자다
  - **저장 데이터는 변환하지 않는다** — 비교 시점에 양쪽을 맞춘다. 운영 중인 앱에서
    기존 데이터를 일괄 마이그레이션하면 되돌릴 수 없다
  - 적용: 단어/카테고리/태그 중복, CSV 가져오기 중복, 퀴즈 채점, 단어 검색
- **수정**: TTS 언어 `en-US` 하드코딩 제거 (`src/utils/speech.ts` 신설)
  - 일본어·중국어·아랍어 단어가 영어 음성 엔진으로 넘어가 무음이거나 엉뚱하게 읽혔다
  - 글자의 유니코드 스크립트로 언어를 추정한다(11개 스크립트 → BCP-47).
    **저장 스키마는 늘리지 않았다** — 기존 사용자 데이터에 그대로 소급 적용된다
  - 한자 단독 표기(`猫`)는 일본어·중국어 구분이 원리적으로 불가능하므로 예문에 가나가
    있으면 일본어로 보정한다. 예문이 없으면 중국어로 둔다(알려진 한계)
  - 기기에 해당 음성이 없으면 **조용히 실패하지 않고** 이유를 토스트로 알린다.
    음성 목록 조회 자체가 실패하면 검사를 건너뛰고 그냥 재생한다(막지 않는다)
  - 목록 조회는 앱 실행당 1회, 재생 전 이전 음성을 끊어 연속 탭 시 겹치지 않게 한다
- **추가**: 다국어 회귀 테스트 48건 (`i18nText.test.ts`, `speech.test.ts`)
  - 13개 언어 CSV 라운드트립(아랍어 모음부호·이모지 ZWJ·구분자 충돌 포함) 무손실 확인
  - NFC/NFD 동등성, 스크립트별 언어 판정, 예문 힌트 보정, 서로게이트 쌍 처리
  - 음성 미지원 분기, 3글자 언어코드(`jpn`)·밑줄 구분자(`en_US`) 인식, 조회 실패 시 재생 허용

    `supportService` 는 화면용 얇은 래퍼로 축소 (export 시그니처 유지)
- **변경**: 버전 게이트를 앱 상수 → 서버 응답 기반으로 이관 **(이번 작업의 핵심)**

    애초에 동작할 수 없었다. 이제 스토어 심사를 기다리지 않고 서버에서 안내를 켤 수 있다
  - `version.latest`(또는 `version.min`) 미만 → 기존 UpdateModal 안내. 건너뛰기·나중에로 닫힌다.

  - 스토어 링크는 서버의 `androidUrl`/`iosUrl` 우선, 없으면 `STORE_URL` 폴백
  - **조회 실패 시 게이트를 적용하지 않는다** — 서버가 죽어도 앱은 평소대로 동작한다
