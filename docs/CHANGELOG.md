### 🔴 토스트 함수가 렌더마다 새로 만들어져 두 화면이 끝없이 다시 그려졌다

화면을 띄워 두고 **손을 뗀 상태**에서 잰 값이다(`top -o %CPU`):

| 화면 | CPU |
|---|---|
| AI 시험 설정 | **130 ~ 158%** (한 코어를 넘긴다) |
| 플래시카드 설정 | **120 ~ 131%** |
| 퀴즈 설정 · 홈 · 통계 · 단어장 · 카테고리 · 마이 | 0 ~ 16% |

`useToast` 가 `showToast` 를 **매 렌더 새로 만들어** 돌려주고 있었고, 그 함수가 두 화면의
`useEffect` 의존성 배열에 들어 있었다. effect 가 매 렌더 다시 돌고, 그 끝에서
`setCategories`(새 배열) · `setSelectedCategoryId` 를 부르니 또 렌더가 돈다 — **스스로를
먹이는 고리다.** 저장소를 세 번씩 다시 읽으면서 끝없이 돈다.

🔴 **그리고 이게 「카테고리를 못 바꾼다」의 정체였다.** 시트에서 줄을 누르면 눌리긴 눌려서
시트가 닫힌다. 그런데 닫히는 순간 저 effect 가 선택을 **첫 번째 카테고리로 되돌린다.**
두 번째 카테고리로는 시험을 볼 수 없었다. 사용자에게는 *"눌러도 안 바뀐다"* 로 보인다.

#### ⚠ 10-13 에 적어 둔 범인(`BottomSheet` 의 `scrollable`)은 **틀렸다**

그날 에뮬레이터에서 *"스크롤 본문을 쓰는 시트만 안 눌리고, `scrollable={false}` 인 확인
시트는 눌린다"* 는 A/B 를 적어 두고 **시트를 쓰는 화면 9개가 위험하다**고 했다. 전부 틀렸다.
실기기에서 **같은 시트 · 같은 탭 방법**으로 대조군을 세우자 바로 갈렸다:

```
퀴즈 설정      → 일본어가 제대로 선택된다   CPU 13%
AI 시험 설정   → 닫히기만 한다              CPU 158%
```

차이는 시트가 아니라 **그 화면의 의존성 배열**이었다.

🔴 **「목록이 스크롤된다」가 결정적 증거였는데 뜻을 뒤집어 읽었다.** 스크롤이 된다는 것은
터치가 시트에 닿고 있다는 뜻이고, 그러면 *"안 눌린다"* 가 아니라 *"눌렸는데 결과가
되돌려진다"* 로 가야 했다. 거기까지 가는 데 두 세션이 걸렸다.

고치는 자리를 화면이 아니라 **훅으로 잡았다**(`useCallback`). 화면의 배열에서 `showToast` 를
빼는 것으로도 이 둘은 멎지만, 다음에 토스트를 쓰는 화면이 같은 자리를 또 밟는다.

가드 `__tests__/useToastStability.test.tsx` 는 **동작으로** 못 박는다 — 렌더를 세 번 돌리고
함수 정체성이 하나인지 본다. 되돌려 놓으면 그 테스트만 빨개지는 것까지 확인했다.
🚫 타입 체크로도 화면을 보는 것으로도 안 잡힌다. 크래시도 경고도 없고 화면은 멀쩡하다.

### 🔴 0문제짜리 AI 시험을 막았다 (사장님 결정)

영어 단어 18개짜리 카테고리에 **한국어**를 고르면 쓸 단어가 0개인데 버튼이
**「0문제로 시작」으로 살아 있었다.** 실기기에서 재현했다.

막는 쪽으로 간 이유는 새 정책이라서가 아니라 **이미 내린 결정과 같은 줄에 세우는 것**이라서다:

```
카테고리에 단어가 0개      이미 막고 있었다
고른 언어의 단어가 0개     안 막고 있었다      ← 사용자가 겪는 일은 똑같다
```

⚠ **「적게 나오는 경우」는 그대로 안 막는다**(2026-10-13 결정). 15문제는 덜 좋은 시험이지
시험이긴 하다. 0문제는 시험이 아니다. 4단어·영어가 여전히 「12문제로 시작」으로 살아 있는
것까지 확인했다.

🔴 **그러다 반대 방향의 거짓을 하나 찾았다.** 안내가 0문제일 때도 *"무료 1회는 그대로
줄어들어요"* 라고 말하고 있었다. 서버는 그 반대다 — `common_server/lib/ai-exam.ts` 가 문제
0개면 **차감 전에** 503 으로 돌려보낸다. 안 나가는 것을 나간다고 겁주는 것도 10-13 에 고친
그 거짓과 같은 잘못이라, 0인 경우의 두 줄을 따로 뒀다.
→ 이 빗장이 실제로 막는 것은 판수가 아니라 **90초를 기다렸다 오류를 받는 길**이다.

두었는데, 어제 더한 쪽에서 그 줄이 안 지켜졌다.

⚠ `subscriptionService.loadModule()` 이 `require` 를 try/catch 로 감싸므로 **조용히 꺼질
가능성이 높다 — 그러나 재 본 적이 없다.** "아마 괜찮다" 위에 사장님 폰을 올리지 않는다.

**버전 이름까지 올린 이유는 따로 있다.** vc24 가 이미 **`1.9.0` 이라는 이름으로** 폰에 깔릴 수
있는 상태다. 같은 이름으로 또 올리면 **설정 화면을 봐도 어느 빌드인지 구분할 수 없다.**

### 🟢 2026-10-14 — AI 시험을 풀다가 **나갈 수 있게** 했다 (사장님 지시)

> *"ai 시험 치다가 중간에 못 나가게하는데 그냥 나갈 수 있게 하면 안돼?"*

#### 🔴 막고 있었는데, 그 막기는 지키지도 못했다

뒤로가기를 누르면 **확인창도 없이** 띠 하나(*"끝까지 풀어 주세요"*)를 띄우고 그 자리에 세웠다.
이유는 *"문제를 만드는 데 돈이 들었고 그냥 나가면 사라진다"* 였다. 그런데 코드를 재 보니:

```
시험 내용은 마지막 문제를 풀어야 저장된다 — 중간 저장이 없었다
  홈 버튼 · 앱 종료 · 오래 끊긴 전화   → 똑같이 사라진다   ✗ 못 막는다
  뒤로가기                           → 막혀 있다          ← 이것 하나뿐
```

🔴 **갇힌 사람은 앱을 강제로 끈다. 그래서 막을수록 더 자주 잃는 구조였다.**
*"막아서 지키고 있다"* 가 **검사도 화면도 통과한 채로 거짓**이었던 자리다.

🔴 **그래서 고친 방향은 「나가게 해 준다」가 아니라 「나가도 안 사라지게 한다」이다.**
문만 열고 저장을 안 붙이면 **정말로 잃기 시작한다** — 그게 더 나쁜 결과다.

#### 들어간 것

```
@my_word_exam_progress   풀다 만 시험 한 판 (접수증 @my_word_exam_job 과 짝 · 동시에 없다)
```

| 언제 적나 | 왜 |
|---|---|
| 문제가 도착한 순간 | 90초를 기다린 직후가 **사람이 가장 많이 나가는 자리**다 |
| 문제를 고를 때마다 | 앱이 죽는 경로를 덮는다. 🔴 **나갈 때만 적으면 그 경로가 그대로 남는다** |
| 「나가기」를 고를 때 | 🔴 **저장이 끝난 뒤에 나간다.** 먼저 나가면 저장이 취소될 수 있다 |

끝내면 비운다(성적표를 보고 나온 사람에게 *"풀던 시험이 있어요"* 가 뜨면 안 된다).
설정 화면 맨 위에 띠가 서고, 새 시험을 시작하려 하면 **먼저 묻는다**(한 판만 들고 있는 설계다).

#### 🔴 여기서 하마터면 밟을 뻔한 것 둘

**① 「나가기」를 시트의 물러서는 자리에 걸 뻔했다.** `ConfirmSheet` 의 `onCancel` 은 **바깥 눌림·
끌어 내리기와 같은 자리**다. 거기 걸면 **시트를 실수로 닫은 사람이 시험에서 나가 버린다.**
→ `cancelLabel` 을 새로 만들어 「계속 풀기」를 그 자리에 두고, **가드로 박았다**(변이 확인함).

**② 「5 / 15 까지 풀었어요」가 하나 더 말하고 있었다**(에뮬레이터에서 눈으로 잡았다).
`index` 는 *보고 있던 문제*이지 *다 푼 개수*가 아니다 — 4번을 풀고 넘기면 `index` 는 5번째가 되는데
그때 *"5까지 풀었어요"* 라고 하면 **하나를 더 풀었다고 말하는 것**이다.
→ **「5 / 15 에서 멈췄어요」**로 바꿨고, 두 확인 시트에서는 숫자를 아예 뺐다(넘긴 문제도 안 푼
것으로 저장돼 「몇 문제까지」를 셀 방법이 애매하다). ⚠ **어제 고친 「문제 20개」 거짓과 같은 종류다.**

#### 🟢 에뮬레이터 실측 — 네 장면 전부 눈으로 봤다

🔴 **실제 시험을 치지 않았다.** 저장본을 손으로 심어서 쟀다 — 시험을 만들면 **돈이 나가고 무료
1회가 줄어드는데**, 이 기능의 검증에는 그게 필요 없다.

| 장면 | 확인 |
|---|---|
| 설정 화면 | 맨 위에 띠 · `5 / 15 에서 멈췄어요` · 잘림 0 |
| 이어서 풀기 | **4번 문제에서 열렸다**(저장된 `index`) · 고른 답이 그대로 |
| 고를 때마다 저장 | 🔴 **저장소를 직접 읽어 확인** — `index 3→4` · `answers[3] = 1` |
| 나가기 | 확인 시트 → 설정 화면 · 띠 숫자가 `4 → 5` 로 따라옴 |
| 새로 시작 | 빨간 「새로 시작」 확인 시트 · 「그만두기」가 물러서는 자리 |

검증: `tsc` 0 · **732/732 · 32/32**(718 → +14) · `check:docs`·`check:licenses` ALL PASS.

#### 🙋 옆에서 발견 — **「0문제로 시작」 버튼이 눌린다**

같은 화면에서 언어를 바꿔 보다 잡았다. 카테고리에 영어 단어 7개가 있는데 언어를 **한국어**로
고르면 화면이 *"0문제만 나와요"* 라고 하면서 **시작 버튼이 「0문제로 시작」으로 살아 있다.**

```
시작을 막는 조건이 "카테고리에 단어가 0개" 다 — "고른 언어의 단어가 0개" 가 아니다
그런데 서버로 보내는 씨앗은 언어로 거르지 않는다
→ 영어 단어로 한국어 시험을 만들고, 무료 1회와 원가가 그대로 나간다
```

🔴 **어제 고친 「문제 20개」 거짓의 경계값이 그대로 남아 있었다.** 어제는 *"적게 나온다"* 만 고쳤고
*"0개면 아예 못 친다"* 는 안 봤다. 🙋 **별건이라 사장님 결정 항목으로 올렸다**(`worklist`).

| 서버 미설정 | **줄 자체를 안 띄운다.** 눌러도 영원히 같은 실패가 나는 버튼을 두지 않는다 |
| 개수를 못 물어봤을 때 | 일반 문구로 남는다 — **설정 화면에 빨간 줄을 띄우지 않는다**(오프라인 규칙) |
| 누르면 | **먼저 다 받고** 묻는다. 받다 실패하면 기기를 아직 안 건드린 채 물러난다 |
| 기기가 비었으면 | 묻지 않고 복구(백업 복원과 같은 규칙) |
| 🔴 버튼 **위** | *"예문 · 태그 · 메모는 서버에 올리지 않아서 돌아오지 않아요"* — 누른 **뒤에** 알게 하지 않는다 |
| 쓰기 | 백업 복원과 **같은 `runRestore`** — 안전 사본 → 덮어쓰기 → `Updates.reloadAsync()` |

#### 🔴 `restoreService.apply()` 를 지웠다 — 아침에 고친 것과 **같은 모양**이었다

부르는 곳도 테스트 참조도 **0건**이었다. 그날 아침 `pushRest()` 가 601개를 통과한 채로
똑같이 비어 있었다. **「함수가 있다」와 「그 함수가 불린다」는 다른 명제이고, 타입 체크는
앞쪽만 본다.** 지우는 쪽을 골랐다 — 남겨 두면 다음 사람이 그걸 부르면서 **안전 사본과
재시작을 같이 건너뛴다**(그쪽이 한 줄 더 짧아 보인다).

#### 시트를 베끼지 않고 넓혔다

`RestoreConfirmSheet` 에 제목 · 아랫줄 이름 · 버튼 글자 · 날짜 숨김 · 추가 안내를 넣었다.
**기본값은 지금 동작 그대로**라 백업 복원 쪽은 한 글자도 안 바뀐다.
🔴 베껴서 두 벌로 만들면 경고 문구가 한쪽만 고쳐지고, 그 어긋남은 **되돌릴 수 없는 버튼
바로 위**에 앉는다.

#### 가드 8개 · 변이 6건 전부 빨개짐

| 깨뜨린 것 | 빨개진 검사 |
|---|---|
| 안전 사본을 지운다 | 덮어쓰기 직전에 남긴다(**자리로** 잰다) |
| 서버 쪽만 따로 쓰게 한다 | 두 통로가 같은 쓰기 함수를 쓴다 |
| 못 되돌리는 것 안내를 지운다 | 버튼 위에서 말한다 |
| 서버 미설정인데도 줄을 띄운다 | 영원히 실패할 버튼을 두지 않는다 |
| 받기 실패를 무시하고 진행한다 | 실패 분기가 쓰기보다 앞이다 |
| 🔴 **부팅 배선에서 복구를 부른다** | **복구를 부르는 곳은 이 화면 하나다** |

🔴 **마지막 줄이 가장 무겁다.** 자동 경로가 언젠가 기기를 덮어쓰는 사고는 **조용하고**,
사용자는 그걸 「단어가 사라졌다」로 겪는다. `src/` 전체를 훑어 부르는 파일을 **센다.**

#### 🔴 여기서 가장 큰 것을 잡았다 — **복구가 삭제가 되는 자리**

화면을 실기기에 띄우고 **서버 행을 직접 세어 보고서야** 보였다:

```
user_words         10 (살아있음 9 · 묘비 1)
user_categories     0      ← ENABLED_KINDS = ['words'] 라 한 번도 안 올라갔다
user_quiz_results   0
user_exams          0
```

그 상태에서 「서버에서 복구」를 누르면 이렇게 된다:

```
받아오는 것   단어 9 · 카테고리 0 · 퀴즈 0 · 성적표 0
덮어쓰기      backupRepo.restore 가 세 종류를 통째로 갈아끼운다 → 전멸
             (성적표도 지워진다 — fetchAll 이 항상 배열 `[]` 을 주므로 "없으면 안 건드린다"
              규칙에 걸리지 않는다)
결과          단어 9개가 **없는 카테고리**를 가리켜 단어장에서 사라진다. 오류는 안 난다
```

🔴 **`fetchAll` 의 `'empty'` 방어는 셋이 전부 0일 때만 막는다.** 단어가 9개라 통과했다.
타입도 테스트도 화면도 멀쩡했다. **숫자를 세어 보는 것 말고는 보이지 않는 종류다**(1.6.0 의
SRS 버그와 같은 자리 — 그때도 `sqlite3` 로 저장본을 뜯은 것이 유일한 오라클이었다).

**고친 방식은 둘이다. 하나에 기대지 않는다:**

| 어디 | 무엇 |
|---|---|
| 줄을 띄울지 | `RESTORE_READY = RESTORE_KINDS.every(isEnabled)` — 🔴 **밀기와 같은 한 줄에 묶었다** |
| 누르는 순간 | 기기에는 있는데 서버가 0인 종류가 있으면 **물러난다** |

🟢 **10-20 에 `ENABLED_KINDS` 를 넷으로 고치면 복구 줄이 저절로 나타난다.** 따로 기억할
것을 만들지 않았다. 그날 `restoreService.test.ts` 의 「지금은 단어만 켜져 있다」가 빨개져서
이 문서와 같은 커밋에서 고치게 만든다.

⚠ **그래서 왕복 ②③ 은 10-20 전에는 잴 수 없다.** 잴 수 있게 하려면 지금 네 종류를 밀어야

- ⚠ 서버의 동기 라우트(`/exam/generate`)는 **그대로 둔다** — 아직 그걸 부르는 번들이 기기에 깔려 있다.

#### #15 공용 시트 — 어둠막은 제자리에서, 시트만 올라온다


- 🔴 **손잡이가 있는데 끌리지 않았다.** 보이는데 안 되는 것은 없는 것보다 나쁘다.
  1/3 넘게 내리거나 0.8px/ms 로 튕기면 닫히고, 아니면 제자리. 위로는 저항 1/5
- ⚠ `Modal` 은 닫힘이 끝난 뒤 내린다(`mounted`) — 바로 내리면 툭 사라진다
- ⚠ 끌기 영역은 **손잡이 + 제목 줄만**이다. 전체에 걸면 안쪽 목록 스크롤과 다툰다

- 🔴 **시안과 다르게 JS 드라이버로 갔다.** 시안은 *"네이티브 + `setValue` 라도 안전"* 이라
  적었지만, 이 저장소에는 **정확히 그 조합으로 당한 기록**이 있다(1.7.0 플래시카드:
  값은 내내 맞았고 틀린 것은 *그 값을 누가 들고 있느냐* 였다). `PanResponder` 는
  `setValue` 를 피할 수 없으므로, **측정으로 뒤집히기 전까지 당해 본 쪽을 믿는다.**

### 추가 — 첫 사용자 안내 (디자인 시안 #2)

단어가 없거나 아직 한 판도 안 풀었으면 홈에 큰 카드와 3단계 안내가 뜬다.

```
단어 0개           안내만 (버튼 7개 숨김) · 카드 = [단어 추가] + CSV 가져오기
단어 ≥1 · 퀴즈 0   안내 + 버튼 둘 다 · ①에 ✓ · 연결선이 ②까지 차오름 · 카드 = [퀴즈 시작]
퀴즈 ≥1            안내가 사라진다
```

- 🔴 **버튼을 숨기는 것은 단어가 0개일 때뿐이다.** 시안은 *"단어가 0개면 버튼 7개 대신"* 이라고만
  적었는데 그걸 "퀴즈를 풀 때까지"로 늘려 읽으면 **단어를 잔뜩 넣어 두고 아직 안 푼 사람이
  단어장·통계에 못 들어간다.** 두 판정을 따로 두고 테스트로 고정했다
- ⚠ 3단계의 ③(복습 알림)은 여기서 ✓ 가 되지 않는다 — 퀴즈를 풀면 패널이 사라지고 기존
  알림 권유 시트가 그 자리를 이어받는다. 같은 일을 두 곳이 조르지 않는다
- ⚠ 히어로의 「단어를 추가하고 학습을 시작해보세요!」 한 줄을 지웠다. 바로 아래 카드가 같은 말을
  더 크게, **누를 곳까지 주면서** 한다
- ⚠ 연결선은 `useNativeDriver: false` 다(높이 값이고, 섞어 쓰다 1.7.0 에서 당했다)

✅ 실기기 확인: 세 언어(한국어·영어·일본어) **잘림 0** · 두 버튼이 올바른 화면으로 가고 **홈으로** 돌아옴 ·
단어를 넣으면 ①에 ✓ 가 찍히고 연결선이 차오르며 버튼이 돌아옴.

  퀴즈가 "단어가 없습니다"로 튕겨 나온다. 지름길이 아니라 함정이 된다
- ⚠ 읽을 때 **모르는 값은 통째로 버린다.** `mode` 에 없는 모드가 들어오면 `QuizScreen` 의

저장해도 **화면을 나가지 않는다.** 버튼이 그 자리에서 스피너 → **초록 ✓ 저장했어요** 로 바뀌고

- ⚠ 앞 화면은 나갈 때 한 번에 반영된다(`onBack` 과 `onWordAdded` 가 같은 일을 하고, 앞 화면은

### 간격 반복(SRS) 자동 복습 — 앱이 "언제 볼지"에 의견을 갖는다

지금까지 앱은 **무엇을 언제 봐야 하는지에 아무 의견이 없었다.** 사용자가 카테고리를 고르고
10문제를 풀 뿐이었고, 유일한 의견인 `취약한 단어` 조차 *"많이 틀린 것"* 이지 *"잊어버릴 때가
된 것"* 이 아니었다 — 어제 맞힌 단어와 3주 전에 맞힌 단어를 똑같이 봤다.

FSRS 의 DSR 모델(난이도·안정도·회상확률)을 직접 옮겨 그 구멍을 메운다. **새로 수집하는
데이터가 없다** — `quizResults` 의 `wordId · isCorrect · takenAt` 이면 충분하다.

- **추가**: 홈 배너 `오늘 복습할 단어 N개` — 누르면 카테고리를 가로질러 10문제
- **추가**: 퀴즈 설정 모드 `복습할 단어` — 고른 카테고리 안에서만
- **추가**: 카테고리 선택에 만기 뱃지 `12개 단어 · 복습 5`
- **변경**: 알림 제목이 `오늘 단어 복습할까요?` → `오늘 복습할 단어 N개`
- **의존성 0개** — 라이브러리를 쓰지 않고 공식을 직접 옮겼다(아래)

🔴 **이 로직에는 눈으로 볼 오라클이 없다.** "내일 뜰 단어가 맞나"는 내일이 와야 알고,
틀려도 크래시가 아니라 **간격만 조용히 이상해진다.** 그래서 테스트를 세 겹으로 세웠다:

| 층 | 무엇을 막나 |
|---|---|
| 정의 | `R(t=S)` 가 정확히 0.9 인가 — S 의 정의 그 자체. 계수를 베끼지 않고 그 조건에서 끌어냈다 |
| 성질 | 맞히면 길어지고 틀리면 짧아지는가 · 잊기 직전에 맞히면 더 크게 오르는가 |
| 황금값 | 간격 수열을 일수로 못 박음 `[3,11,35,101,270,672,1571]` — 가중치 19개 중 한 자리만 틀려도 걸린다 |

**상태는 파생값이라 백업에 담지 않는다.** `s·d·만기`는 전부 `words + quizResults` 에서 다시
만들어진다. 담으면 얻는 정보는 0인데 백업의 만기와 재생의 만기가 어긋날 자리만 생긴다
(통계를 저장하지 않고 매번 파생하는 것과 같은 판단). 그 판단이 성립하려면 **언제 재생해도
같은 답**이 나와야 하므로, 그것을 테스트로 못 박았다.

- 자가 치유는 `builtFrom`(재생에 쓴 결과 개수) 한 값이 한다. 저장된 배열 길이와 다르면 재생한다
- 🔴 그 검사로 못 막는 구멍 하나는 `restore()` 에서 끊었다 — **개수만 같고 내용이 다른** 백업
- 🔴 **재생은 읽기 전용이다.** `quizResults` 를 고치면 정답률·스트릭이 함께 흔들린다
