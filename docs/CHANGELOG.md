## [1.6.0] - 개발 중 (2026-09-08~)

### 간격 반복(SRS) 자동 복습 — 앱이 "언제 볼지"에 의견을 갖는다

지금까지 앱은 **무엇을 언제 봐야 하는지에 아무 의견이 없었다.** 사용자가 카테고리를 고르고
10문제를 풀 뿐이었고, 유일한 의견인 `취약한 단어` 조차 *"많이 틀린 것"* 이지 *"잊어버릴 때가
된 것"* 이 아니었다 — 어제 맞힌 단어와 3주 전에 맞힌 단어를 똑같이 봤다.

FSRS 의 DSR 모델(난이도·안정도·회상확률)을 직접 옮겨 그 구멍을 메운다. **새로 수집하는
데이터가 없다** — `quizResults` 의 `wordId · isCorrect · takenAt` 이면 충분하다.

- **추가**: 홈 배너 `오늘 복습할 단어 N개` — 누르면 카테고리를 가로질러 10문제
- **추가**: 퀴즈 설정 모드 `복습할 단어` — 고른 카테고리 안에서만
- **추가**: 카테고리 선택에 만기 뱃지 `12개 단어 · 복습 5`
- **변경**: 알림 제목이 `오늘 단어 복습할까요?` → `오늘 복습할 단어 N개`
- **의존성 0개** — 라이브러리를 쓰지 않고 공식을 직접 옮겼다(아래)

🔴 **이 로직에는 눈으로 볼 오라클이 없다.** "내일 뜰 단어가 맞나"는 내일이 와야 알고,
틀려도 크래시가 아니라 **간격만 조용히 이상해진다.** 그래서 테스트를 세 겹으로 세웠다:

| 층 | 무엇을 막나 |
|---|---|
| 정의 | `R(t=S)` 가 정확히 0.9 인가 — S 의 정의 그 자체. 계수를 베끼지 않고 그 조건에서 끌어냈다 |
| 성질 | 맞히면 길어지고 틀리면 짧아지는가 · 잊기 직전에 맞히면 더 크게 오르는가 |
| 황금값 | 간격 수열을 일수로 못 박음 `[3,11,35,101,270,672,1571]` — 가중치 19개 중 한 자리만 틀려도 걸린다 |

**상태는 파생값이라 백업에 담지 않는다.** `s·d·만기`는 전부 `words + quizResults` 에서 다시
만들어진다. 담으면 얻는 정보는 0인데 백업의 만기와 재생의 만기가 어긋날 자리만 생긴다
(통계를 저장하지 않고 매번 파생하는 것과 같은 판단). 그 판단이 성립하려면 **언제 재생해도
같은 답**이 나와야 하므로, 그것을 테스트로 못 박았다.

- 자가 치유는 `builtFrom`(재생에 쓴 결과 개수) 한 값이 한다. 저장된 배열 길이와 다르면 재생한다
- 🔴 그 검사로 못 막는 구멍 하나는 `restore()` 에서 끊었다 — **개수만 같고 내용이 다른** 백업
- 🔴 **재생은 읽기 전용이다.** `quizResults` 를 고치면 정답률·스트릭이 함께 흔들린다

**딸려 고쳐진 기존 결함**: 객관식 오답 보기를 같은 카테고리에서만 뽑고 모자라면
`기억나지 않음`·`해당 없음` 더미를 넣고 있었다. 단어 4개 미만 카테고리는 정답이 눈에 띄었다.
복습 큐가 카테고리를 가로지르며 후보 풀이 전체가 되어 사라진다.

**알림 동작이 바뀌었다** — 그날 볼 것이 없으면 **그날은 예약하지 않는다.** 예약이 7개보다
적은 것이 정상이 됐다(볼 것 없는데 오는 알림은 사람이 알림을 끄게 만든다).

- **제거**: `quizService.getReminderWords` — 유일한 호출자가 사라져 죽은 코드가 됐다.
  남기면 그 테스트가 "살아 있는 로직을 지킨다"는 거짓 인상을 준다

## [1.5.0] - 미출시 (2026-09-07 작성 · 업로드는 다음 주)

### 내가 만들고 내가 옮길 수 있는 백업

안드로이드 자동 백업이 이미 단어를 덮고 있지만(`allowBackup=true`), 사용자는 그것을 **만들 수도
볼 수도 없다.** 재설치 경로에서만 복원되고, 하루에 한 번 조건부로 돌며, 계정·플랫폼을 못 넘는다.
그래서 "데이터가 사라진다"가 아니라 **"통제할 수 있는 백업이 없다"** 를 푼다.

- **추가**: 설정 → 데이터 → `백업 파일 만들기` · `백업에서 복원`
  - 파일 하나(JSON)에 **카테고리 + 단어 + 퀴즈 기록 + 설정**을 담는다. 기존 CSV 는 손대지 않았다
  - 저장 위치를 앱이 정하지 않고 **공유 시트**로 넘긴다 — 앱이 정한 폴더는 사용자가 못 찾는다
- **추가**: `expo-file-system` · `expo-sharing` · `expo-document-picker`

🔴 **통계가 되살아나는지가 이 기능의 전부다.** 통계는 저장된 값이 아니라
`words[].createdAt` · `quizResults[].takenAt` 에서 매번 계산되는 파생값이라, 복원이 조용히
틀릴 자리가 셋 있고 셋 다 크래시 없이 숫자만 바꾼다:

| 실수 | 증상 |
|---|---|
| 날짜를 "지금"으로 다시 씀 | 몇 달치 활동이 **복원한 날 하루로 뭉침**(스트릭 1일) |
| `@my_word_next_id` 누락 | 새 단어가 기존 id 를 받아 **퀴즈 기록이 엉뚱한 단어에 붙음** |
| 고아 결과(삭제된 단어) 정리 | 총 퀴즈 수·정답률이 백업 시점과 달라짐 |

→ 오라클 하나로 못박았다: **복원 직후 통계 == 백업 시점 통계.** 복원이 날짜를 다시 쓰도록
변이시켜 테스트가 무는 것을 확인했다.

- **복원은 전체 교체다 — 병합하지 않는다.** ID 재매핑은 할 수 있지만 퀴즈 기록을 합칠 때
  답이 없는 질문이 생긴다(같은 단어의 정답률 80%/20% 를 합치면?). 더 나쁜 건 스트릭이다 —
  두 기기의 활동일을 합치면 **실제로 하지 않은 연속 학습이 만들어진다.** 부분 추가는 기존
  CSV 가져오기가 이미 한다
- 확인 화면은 "덮어쓸까요?"가 아니라 **양쪽 숫자**를 보여 준다. 잃을 것이 없으면(새 기기) 안 묻는다
- 복원 직전 현재 상태를 파일로 한 벌 남긴다 — 되돌릴 수 없는 작업의 유일한 방어선
- 🔴 **백업에 담지 않는 것**: `@my_word_ad_free`(광고 제거 **구매 캐시** — 담으면 결제 우회
  경로가 된다) · `myword_device_id`(문의 귀속 자격증명). 테스트로 못박았다

### 일본어 추가 — 스토어는 일본어인데 앱이 영어였다

`ja-JP` 스토어 등록정보로 유입되는 사용자가 **영어 앱**을 받고 있었다. 출시 노트는 세 언어를
다 채우고 있어 등록정보만 보면 드러나지 않는 불일치였다.

- **추가**: `src/i18n/locales/ja.json` — 447키 전부. 설정 → 언어에 `日本語`
- 기기 언어가 일본어면 **설정 없이 자동 적용**된다(저장된 설정 → 기기 언어 → en 폴백)
- 사전 조회는 손댈 것이 없었다 — 번역 타겟이 앱 언어를 그대로 따르고 Google 번역이 `ja` 를 지원한다
- 🔴 `partOfSpeech` 가 `Record<AppLanguage, …>` 라 **타입 체커가 일본어 품사표를 요구했다.**
  언어를 늘리면 컴파일이 막히는 구조여서 빠뜨릴 수 없다

🔴 **i18next 는 없는 키를 오류 없이 키 그대로 출력한다.** 이 앱에서 키는 한국어 원문이라,
번역이 하나 빠지면 일본어 화면에 **한국어가 그대로 뜬다.** tsc 도 lint 도 못 잡아서 기계로
막았다(`__tests__/i18nLocales.test.ts`) — 키 커버리지 · 죽은 번역 · 빈 번역 · 보간 자리표시자 ·
**그 언어가 실제로 쓰는 복수형 카테고리**(`Intl.PluralRules` 가 진실이다. 일본어는 `other`
하나뿐이고 영어는 둘이다).

## [1.4.0] - 2026-09-07

### 하루 안 쓰면 알려 준다 — 로컬 학습 알림

앱을 하루 열지 않으면 정해진 시각에 복습을 권한다. **서버·FCM·푸시토큰을 쓰지 않는다** —
알림은 기기 안에서 만들어져 기기에 표시되고 밖으로 나가지 않는다("백엔드 없음"을 그대로 둔다).

- **추가**: `expo-notifications` — 설정에 토글 + 시각 선택(기본 **20:00**), 시각은 5분 단위
  - 예약 규칙: 앱을 열 때마다 **전부 취소하고 내일부터 7일치를 다시 건다.**
    앱이 꺼져 있으면 "오늘 썼나"를 검사할 코드가 돌지 않으므로, 조건을 트리거 시점이 아니라
    **예약하는 순간에 미리 반영**하는 수밖에 없다. 열수록 첫 알림이 밀려 "하루 안 쓰면 온다"가 된다
  - 7일 내내 안 열면 멈춘다 — 떠난 사용자에게 계속 보내지 않는다
- **추가**: 알림 문구에 **실제 단어**를 넣는다. ① 아직 한 번도 안 푼 단어(오래 방치한 것부터)
  ② 정답률 낮은 순, 같으면 덜 풀어 본 순
  - 🔴 기존 `getWordQuizStats()` 는 **퀴즈 결과에서 출발**해 결과 없는 단어를 담지 않는다 —
    그걸 썼다면 "안 푼 단어"가 영원히 안 뽑히면서도 함수는 멀쩡히 값을 반환했을 것이다.
    저장된 단어에서 출발하는 `getReminderWords()` 를 따로 만들었다
  - 단어가 0개면 예약하지 않는다 — 빈 앱에 오는 "복습하세요"는 알림을 끄게 만든다
- **추가**: 첫 퀴즈를 끝내고 **홈으로 돌아왔을 때** 한 번만 권유하는 시트
  - 🔴 퀴즈 결과 화면에 두지 않았다 — 그 화면은 진입 500ms 뒤 전면 광고를 띄워 시트와 겹친다
  - 안드로이드는 한 번 거절당하면 앱이 다시 못 묻는다. **어디서 묻느냐가 되돌릴 수 없는 선택**이다
- **기본 시각이 21:00 이 아닌 이유**: 정보통신망법 §50③ 이 **21:00~08:00** 전송에 별도 동의를
  요구한다. 로컬 생성 + 사용자가 켠 알림이라 적용 대상으로 보기 어렵지만, 기본값을 하필 그
  시간대 시작점에 두면 공짜로 논쟁을 산다. 사용자가 직접 야간 시각을 고르는 것은 막지 않는다
- **알림 채널 가시성 `PRIVATE`** — 본문에 저장한 단어가 들어가므로, 기기에서 "잠금화면에 민감한
  내용 숨김"을 켠 사람의 선택이 지켜져야 한다

## [1.3.3] - 2026-09-01

### 문의에 답할 수 있게 만든다 — 기기 귀속 + 활성 하트비트

1.0.0 이래 문의는 **완전 익명**이었다. 그래서 받아도 **답할 방법이 없었다** — 보낸 사람이
누구인지가 아니라 *어느 기기로 돌려보내야 하는지*를 몰랐다. 계정을 만들지 않고 그것만 푼다.

- **추가**: `expo-secure-store` · `expo-crypto` — 첫 실행에 UUID v4 를 만들어 **SecureStore** 에 둔다
  - 🔴 **AsyncStorage 가 아니다.** 이 값은 문의 이력에 붙는 자격증명이라 평문 저장소에 두지 않는다
  - 🔴 **`deviceId` 와 세션 토큰은 로그에 찍지 않는다.** `__DEV__` 로그도 성공/실패만 남긴다
  - SecureStore 키에는 `@` 를 못 쓴다 — `myword_device_id`(기존 AsyncStorage 키 규약과 다르다)
- **변경**: `BootstrapContext` 가 부팅 시 `ensureDeviceSession()` 을 **기존 두 호출과 나란히** 부른다
  (`Promise.all` — 부팅이 느려지지 않는다). 이 요청 하나가 **활성 기기 집계(DAU)** 도 겸한다
  - 🔴 **실패하면 조용히 삼킨다.** 서버가 죽어도, 오프라인이어도 앱은 평소대로 뜬다.
    문의 기능만 "전송 실패"를 말할 뿐 부팅 경로에는 오류 표시가 **0건**이다
