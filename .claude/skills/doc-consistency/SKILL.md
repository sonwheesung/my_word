# doc-consistency (My Word) — 문서 정합 검사

> 범용 방법론은 `C:\project\common\.claude\skills\doc-consistency\SKILL.md` 에 있다.
> 여기에는 **이 레포의 문서 지도 · 정본 순서 · 검사 명령 · 기지 오탐**과, My Word 에서 실제로 난 **축 ⑦** 만 둔다.
>
> 경계: 코드가 명세대로 *도는가*는 `npm test` · `check:tests` · 에뮬레이터가 본다. 이건 **문서 자체가 진실과 맞나**다.

## 0. 먼저 기계를 돌린다. 사람은 문장을 본다

```bash
npm run check:docs       # 화면·서비스·컴포넌트·저장 키 목록이 문서와 코드에서 같은가 (축 ⑦ 의 셀 수 있는 부분)
npm run check:licenses   # 게시 중인 오픈소스 고지가 설치본·앱 버전과 같은가
npm run check:tests      # 테스트가 실제로 몇 개 돌았나 (문서에 테스트 개수를 적지 않는 이유)
grep -m1 "^## \[" docs/CHANGELOG.md   # 최신 항목 vs app.json version
```

🔴 **가드가 초록이면 가드가 세는 것만 맞다.** `check:docs` 는 이름이 문서에 *있나* 까지만 본다.
그 화면 설명이 코드와 같은지는 못 본다(2026-09-18 에 이름은 있는데 설명이 반년 낡은 절을 여럿 봤다).
그래서 아래 축은 가드가 초록이어도 사람이 한다.

## 2. 축 ⑦: 목록 문서가 코드보다 적다 (**My Word 의 지배적 결함**)

다른 레포는 ⑤(과장)나 ⑥(끝난 일)이 제일 많은데, My Word 는 **기능을 더할 때 목록 문서를 안 따라 고친다.**
기능마다 CLAUDE.md 에는 긴 절이 생기는데, 구조 문서는 3월에 멈춰 있었다.

| 2026-09-18 실측 | 문서가 적은 것 | 실제 |
|---|---|---|
| `screens.md` · `architecture.md` | 화면 9개 | **15개** (설정 · 문의 · 공지 · 단어 받기 · 플래시카드 설정 · 플래시카드가 없었다) |
| `README.md` | 화면 13개 · 테스트 13스위트 199개 · runtimeVersion `1.3.3` | 15개 · 16스위트 288개 · **`1.6.0`** |
| `data-model.md` | 저장 키 4개 | **14개** + SecureStore 키 |
| `services-api.md` | 서비스 4개 | **13개** + `commonServer/` |
| `architecture.md` 컴포넌트 | 4개 | **12개** (+ 웹 대체 구현 `.web.tsx` 1개) |

🔴 **개수만 틀린 것이 아니었다.** 목록에서 빠진 것은 설명도 없고, 목록에 있던 화면도 **설명이 틀렸다**
(퀴즈가 주관식만 적혀 있었는데 객관식 · 복습 모드가 있었다). **개수 드리프트는 내용 드리프트의 겉면이다.**
→ 개수를 맞추고 끝내지 않는다. 빠진 것을 채울 때 **옆 항목의 설명도 코드와 대조한다.**

### 검사법

1. `npm run check:docs` 가 이름 집합을 대조한다(개수가 아니라 차집합 · 양방향).
   만든 날(2026-09-18) 일부러 망가뜨려 봤다: 화면 이름 바꾸기 · 키 이름 바꾸기 · README 개수 틀리기 → 전부 FAIL.
   🔴 그때 **키 이름 바꾸기가 한쪽 방향에서 초록**이었다. `@my_word_srs` 가 `@my_word_srs_old` 안에서 부분 문자열로 찾아졌다.
   이름 경계로 찾게 고쳤다. **통과만 본 가드였으면 이 구멍을 몰랐다.**
2. 초록이면, 최근 기능 릴리스(CHANGELOG 의 최근 3개)가 건드린 화면 · 서비스의 **설명 절**을 코드와 대조한다.
3. 문서가 적은 **동작 서술**(몇 개 · 몇 ms · 어느 방향 · 무엇을 저장)을 코드 상수로 확인한다.

### 🔴 쓰는 쪽 규칙 (다음 드리프트를 막는다)

- **새 화면 · 서비스 · 저장 키를 만든 커밋에 문서 한 줄을 같이 넣는다.** 안 넣으면 `check:docs` 가 빨개진다.
- **README 에 개수를 손으로 적지 않는다.** 적어야 하면 가드가 재는 것(`화면 N개`)만 적는다.
  테스트 개수는 `scripts/check-tests.mjs` 의 바닥값이 정본이다.

## 3. 축 ⑥: 끝난 일이 남은 일로 남았나

```bash
grep -n "^\s*- \[ \]" docs/*.md CLAUDE.md README.md worklist-*.md
grep -nE "⏸|아직|미검증|검증이 남았다|확인할 것|미구현|승인 대기|대기" CLAUDE.md README.md docs/*.md | grep -v "~~" | grep -v CHANGELOG
```

2026-09-18 에 걸린 것:

| 자리 | 적힌 것 | 실제 |
|---|---|---|
| `CLAUDE.md` R8 절 | *"심사 통과 후 확인할 것: 난독화 경고가 사라지는가"* | 같은 절 위에 **"경고가 사라졌다"** 가 이미 있다 |
| `CLAUDE.md` 최적화된 리소스 축소 절 | *"🔴 검증이 남았다. 다음 릴리스를 구울 때 반드시 한다"* | 9-14 1.7.0 에서 검증했다(바로 위 줄의 취소선만 고쳐졌다) |
| `docs/I18N_PLAN.md` | *"상태: 승인 대기"* | 한국어 · 영어는 1.2.0 에, 일본어는 1.6.0 에 나갔다 |
| `docs/CHANGELOG.md` 1.5.0 제목 | *"미출시 · 업로드는 다음 주"* | 스토어에 따로 나가지 않고 **1.6.0 에 합쳐졌다**(같은 파일 1.6.0 절) |

🔴 이 표를 쓰던 사람도 처음에 *"일본어는 1.5.0 으로 나갔다"* 고 적었다. 1.5.0 절이 길게 있으니 나간 것처럼 보인다.
**버전 번호가 있는 절 = 나간 릴리스가 아니다.** 게시 여부는 CHANGELOG 의 게시 줄이나 콘솔로 본다.

★ 셋 다 **"끝났다고 적는 일"이 작업의 마지막 칸**이라 빠졌다. 한 줄은 고치고 **같은 사실을 말하는 옆 줄**을 안 고쳤다.
→ 끝났다고 적을 때는 `grep` 으로 **그 사실을 말하는 다른 줄**을 찾아 함께 닫는다.

⚠ `⏸` 는 "못 한 것"과 "안 하기로 한 것" 둘 다에 쓰인다. 후자면 그대로 둔다.
⚠ 근거를 못 찾으면 닫지 않는다. 닫는 것도 주장이다(축 ⑤).
🔴 **그런데 "근거가 없다"도 주장이다.** 2026-09-18 감사는 OTA 번들 주소 검사(CLAUDE.md OTA 절 `⏸`)를
"9-14 에 돌린 흔적은 있으나 판정 기록이 없다"며 열어 뒀다. 같은 날 OTA 를 내려고 CHANGELOG 를 보니
**9-14 OTA 줄에 "발행 전 번들 주소 검사 통과"가 이미 적혀 있었다.** 세션 기록만 뒤지고 CHANGELOG 를 안 본 탓이다.
→ 열어 두기 전에 **그 일이 남겼을 자리**(CHANGELOG · 인계 문서 · 커밋 메시지)를 grep 한다.

## 4. 축 ⑤: 검증 주장 과장

이 레포의 릴리스 검증 표(CLAUDE.md 1.4.0~1.7.0 절)는 **근거 열이 있어서** 과장이 드물다. 그 형식을 지킨다.
과장이 나는 곳은 근거 열이 없는 자리다: 인계 문서의 "끝낸 것", 커밋 메시지, 사용자 보고.

- 강등 어휘: `코드로 확인 · 화면으로는 안 봄` · `계산상` · `⏸ 실기기 미측정`
- 🔴 **0 이 나오면 대상이 아니라 세는 방법을 의심한다.** `aapt2` 로 알림 아이콘이 0줄로 나왔을 때 검색식이 틀렸었다(CLAUDE.md 1.7.0 절).
- 🔴 새 가드는 **일부러 망가뜨려 빨개지는 것**까지 본다. 통과만 본 가드는 허위 오라클이다.

## 5. 축 ①~④: 명령

```bash

  | sort -u | while read f; do case "$f" in http*|file:*) continue;; esac; [ -e "$f" ] || [ -e "docs/$f" ] || echo "MISSING: $f"; done
grep -ohE "\`(src|scripts|__tests__|docs|assets|android)/[A-Za-z0-9_./-]+\`" README.md docs/*.md CLAUDE.md | tr -d '`' \
  | sort -u | while read f; do [ -e "$f" ] || echo "MISSING: $f"; done
grep -ohE "npm run [a-z:0-9-]+" README.md docs/*.md CLAUDE.md .claude/SKILL.md | sort -u   # package.json scripts 와 대조

# ② 한 사실에 두 값: 교차축은 아래 표
# ③ 반대 방향: 코드의 큰 것이 문서에 홈이 있나 → check:docs 가 화면·서비스·컴포넌트·키를 본다.

```

설명을 코드에서 **다시 뽑는 일 자체가 코드 리뷰가 된다**는 것이 이 축의 부수 효과다.
